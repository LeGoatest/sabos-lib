# READMEbasic README and Documentation Glossary

> **Status:** Informative

## Badge
A small visual status or metadata label, often generated by services such as Shields.io. A badge should communicate verified project state rather than decorative technology affiliation.

## Canonical documentation
The authoritative source for a topic. A README should normally route readers to canonical deep documentation instead of duplicating it in full.

## Changelog
A human-curated record of notable changes over time. It is distinct from git history and from a README, which describes the current project state.

## First success
The earliest concrete outcome showing that installation/setup worked—for example a passing command, rendered application, imported package, or other reproducible result.

## Front door
READMEbasic shorthand for the README's role as the initial orientation surface of a repository or package, rather than the entire documentation system.

## High-signal badge
A badge that conveys adoption-relevant state such as build status, release version, license, runtime requirement, or supported framework version.

## Progressive disclosure
Presenting the minimum information needed at the current level and linking to deeper, more specialized documentation as the reader's need becomes more specific.

## README profile
The audience/role classification used to select an appropriate README structure, such as application, library/package, multi-system repository, documentation/governance repository, or subsystem/component.

## Repository-relative link
A link to another file or path within the same repository using a relative path so it remains usable across branches, forks, and local clones where applicable.

## Template debris
Placeholders, fake links, sample usernames, TODO badges, irrelevant optional sections, example credentials, or generic boilerplate accidentally left in a published README.

## User-facing contract
A command, path, version, compatibility statement, status, feature claim, or other README assertion that a user may rely on and that therefore should stay synchronized with repository evidence.
