# Documentation Routing

Inherit [SETUPbasic/AGENTS.md](../AGENTS.md) and [repository governance](../../governance/README.md).

When adding or revising a model:
1. Identify its **axis** and whether it is a full architecture, composition technique, delivery model, data pattern, or deployment pattern.
2. Give its definition, responsibility boundary, sample file or component arrangement, benefits, trade-offs, suitability, and compatibility (or reference the full profile).
3. Cite an originating practitioner work, specification or vendor source where possible; date/version-qualify changing platform claims.
4. Avoid double-counting synonyms as distinct architectures without explaining the relationship.
5. Preserve user-selected design decisions as project-specific evidence, not binding rules for all adopters.
6. Update model index, glossary, decision guide and examples where affected, maintaining valid relative links.
7. Do not promote reference material to a binding requirement without intentional governance change.
