# Changelog

All notable changes to WDBASIC will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/).

## [Unreleased]

### Added

- `docs/` as the canonical home for WDBASIC's substantive architecture, standards, contracts, profiles, positions, compliance/evidence, authoring, token, component, glossary, and cross-cutting knowledge.
- `docs/framework-contract.md` preserving the former full root WDBASIC v2 contract while allowing the root README to become a concise entrypoint.
- `docs/implementation-agent-contract.md` preserving the former detailed root agent instructions while allowing root `AGENTS.md` to become a compact router.
- `docs/README.md` and `docs/AGENTS.md` as the WDBASIC knowledge index and documentation authority router.
- `engineering-validation.md` defining the Thorough, Early, Systematic, Transparent, Independent, Non-destructive, and Gradual implementation-validation philosophy.
- WDBASIC integration with repository-wide authority, invariant, mutation, and evidence governance.
- Local `AGENTS.md` files for forms, tokens, components, compliance, authoring, profiles, and glossaries so automated work is routed through the nearest subject authority instead of relying only on the WDBASIC root instructions.
- `positions/` with local agent governance as the explicit home for deliberate WDBASIC practitioner preferences, tradeoffs, and divergence from common industry/framework practice.
- This subsystem changelog.

### Changed

- Moved WDBASIC long-form knowledge and subject directories under `docs/` while preserving their substantive contract authority.
- Reworked the root `README.md` into a concise WDBASIC entrypoint that routes readers into `docs/`.
- Reworked root `AGENTS.md` into a compact router while preserving the prior detailed implementation safeguards under `docs/implementation-agent-contract.md`.
- Clarified that the `docs/` move is structural governance and does not weaken existing WDBASIC contracts by relocation alone.
- Clarified that engineering validation is separate from SEObasic's canonical T.E.S.T.I.N.G. content philosophy.
- Strengthened regression boundaries for automated implementation work through the repository governance layer.
- Clarified distributed contract ownership: forms, tokens, components, compliance, authoring, and profiles keep their contracts with the subject domain rather than being flattened into one central contract directory.
- Separated practitioner positions from formal standards and binding contracts so WDBASIC preferences can be preserved without being mislabeled as universal requirements.
- Updated the canonical WDBASIC README document map and reading order to expose `engineering-validation.md`, `positions/`, and the local `AGENTS.md` boundaries for forms, tokens, components, compliance, authoring, profiles, and glossaries.
