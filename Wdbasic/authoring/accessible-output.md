# WDBASIC Accessible Output Contract

> **Authority:** Binding generated-content contract  
> **ATAG dependency:** [`atag-2.0.md`](atag-2.0.md)  
> **Component dependency:** [`../components/component-contracts.md`](../components/component-contracts.md)

This contract governs HTML, fragments, templates, emails, exports, and other content produced by an authoring tool.

## 1. Output principle

Generated output must be accessible by default and must not depend on post-publication repair for predictable failures.

The output contract applies to:

- Full pages.
- HTMX fragments.
- Reusable sections and widgets.
- Form markup.
- Navigation.
- Structured data tables.
- Media embeds.
- Transactional and marketing emails when generated by the product.
- Exported HTML and documents where applicable.

## 2. Document output

A complete page must provide:

- Correct document language and direction.
- Unique meaningful title.
- One discoverable main region.
- Logical headings.
- Bypass mechanism for repeated blocks.
- Crawlable navigation where public.
- Correct status and canonical URL behavior.
- Metadata managed by the product.

## 3. Component output

Generated components must:

- Use native HTML first.
- Provide complete states.
- Generate unique IDs.
- Preserve valid relationships.
- Provide accessible names and descriptions.
- Maintain keyboard behavior.
- Return correct server and ARIA state.
- Remain usable without enhancement scripts where required.

Do not generate a visual component without the behavior required by its semantic role.

## 4. Images

The output system must support:

- Meaningful alternative text.
- Explicit decorative treatment.
- Captions and attribution.
- Stable dimensions.
- Responsive sources.
- Permission and source records.

Do not automatically copy filenames into alternative text as a final value.

## 5. Links and actions

- Links must have meaningful destinations and names.
- Buttons must perform actions.
- Empty controls are prohibited.
- Visible labels must be included in accessible names.
- Repeated generic actions must identify their target.
- New-window behavior must be deliberate and communicated when material.

## 6. Forms

Generated forms must include:

- Persistent labels.
- Correct control type.
- Name and submitted value.
- Autocomplete when appropriate.
- Instructions and constraints.
- Required status.
- Error association.
- Error summary for complex forms.
- Server validation and preserved input.
- Success and recovery states.

## 7. Tables

Generated data tables must preserve:

- Caption or accessible purpose.
- Header cells.
- Scope or header relationships.
- Logical reading order.
- Sort state and named controls.
- Header/value relationships at narrow widths.

A visual card transformation must not destroy tabular relationships.

## 8. Media

Generated media output must carry the applicable caption, transcript, description, control, and autoplay requirements from [`../media-accessibility.md`](../media-accessibility.md).

The tool must not publish media while required accessibility metadata is silently discarded.

## 9. Localization

Generated output must preserve:

- `lang` and `dir`.
- Passage-language metadata.
- Locale formatting.
- Bidirectional isolation.
- Translated labels, errors, captions, and metadata.

See [`../internationalization.md`](../internationalization.md).

## 10. Sanitization and preservation

Sanitization must remove unsafe content without unnecessarily removing accessibility semantics.

The sanitizer policy must deliberately handle:

- `aria-*` attributes.
- `role`.
- `lang` and `dir`.
- IDs and references.
- Table semantics.
- Form attributes.
- Caption and media tracks.

Unsafe ARIA is not preserved merely because it is accessibility-related.

## 11. Import and migration

When importing existing content:

- Preserve valid semantics.
- Identify unsupported constructs.
- Report accessibility metadata that cannot be mapped.
- Avoid converting semantic structures into presentational markup.
- Provide a review queue for uncertain repairs.

## 12. Output verification

Test generated output for:

- HTML and relationship integrity.
- WCAG coverage.
- Repeated component rendering.
- No-JavaScript baseline where applicable.
- HTMX replacement.
- Localization and RTL.
- Media equivalents.
- Security policy compatibility.
- Email-client or export-format limitations when applicable.

## 13. Output record

```yaml
  templates: <path>
  components: <path>
  sanitizer_policy: <path>

  accessibility_checks: <path-or-command>
  import_mapping: <path>
  known_limitations: []
  owner: <role>
```
