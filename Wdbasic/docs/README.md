# WDBASIC Documentation

> **Status:** Canonical WDBASIC knowledge index  
> **Framework root:** [`../README.md`](../README.md)  
> **Agent instructions:** [`AGENTS.md`](AGENTS.md)

`Wdbasic/docs/` contains WDBASIC's governed architecture, standards, accessibility, forms, security/privacy, validation, authoring, compliance, profiles, tokens, components, positions, and terminology.

WDBASIC is primarily a knowledge/contract system, so most of its substantive material belongs here rather than beside the framework entrypoint files.

## Knowledge domains

- `architecture_rules.md` — binding architecture rules.
- `STANDARDS.md` — standards and applicability registry.
- `engineering-validation.md` — WDBASIC engineering-validation philosophy.
- `cognitive-accessibility.md`, `internationalization.md`, `media-accessibility.md`, `non-web-accessibility.md` — cross-cutting accessibility/content concerns.
- `security-and-privacy.md` — security/privacy contract surface.
- `sustainability.md` — sustainability guidance.
- `forms/` — form lifecycle, validation, and security contracts.
- `compliance/` — accessibility evidence, testing methodology, matrices, statements, and reusable evidence templates.
- `authoring/` — authoring-tool and accessible-output guidance.
- `profiles/` — design/adoption profiles.
- `tokens/` — semantic token contracts.
- `components/` — reusable component contracts.
- `positions/` — deliberate practitioner positions.
- `glossaries/` — terminology and disambiguation.

## Authority

The framework root [`../README.md`](../README.md) remains the human entrypoint. Binding architecture and standards now live under this documentation tree, with the nearest local `AGENTS.md` controlling subject-specific automated work.

Documentation relocation does not change the substantive authority of an existing contract merely because its path moved under `docs/`.
