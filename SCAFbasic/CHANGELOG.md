# Changelog

SCAFbasic changes are tracked here; repository-wide routing changes also appear in the root changelog.

## [Unreleased]

### Changed
- Clarified explicit user-authorized placeholder scaffolds as an exception to the default preference for only needed folders; tracked folders are not proof of implemented or registered capabilities.
- Distinguished proposed, placeholder, code-present, validated and deployed states in directory guidance, selection criteria and the proposed review contract.
- Expanded source/generated-asset evidence guidance and the Laravel example without requiring any particular build tool or forcing application refactors.
- Renamed the original SETUPbasic documentation scope to SCAFbasic (scaffolding) while preserving the architecture catalog and examples.

### Added
- Added framework-neutral Contracts, Abstractions and Capability Operations guidance, including ownership and interface boundaries, role-aware workflows, operation naming, authorization/scope, privacy, auditing, transaction/idempotency semantics, a reusable profile and a generic content-revision example. This defines structure, not a mail subsystem or any particular UI product.
- Established SCAFbasic as the architecture-model and site/application-structure knowledge system.
- Defined and classified system topology, application/domain organization, web presentation, data-access and integration models, with comparison and compatibility guidance.
- Added structure/naming guidance, an architecture decision process, an explicitly proposed review contract, primary references and three illustrative site trees.
